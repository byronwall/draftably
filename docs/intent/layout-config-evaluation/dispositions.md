# Recommendation dispositions

The [175-row original inventory](assets/pro-results/2026-11-01/draftably-evaluation/inventory.csv)
uses Keep, Hide, Merge, Automate, and Remove for individual surfaces. Those labels do not all
authorize new automatic behavior. The integration decisions below use Build, Explore, Defer, and
Avoid. [dispositions.csv](dispositions.csv) assigns every original ID a reviewed class and reason.

Build means included in the proposed plan. It does not mean implemented or approved to ship.
The CSV covers 115 Build, 13 Explore, 41 Defer, and 6 Avoid decisions. Build rows include
preservation requirements; they are not 115 separate features.

| Recommendation group                                                     | Disposition    | Reason                                                                                      |
| ------------------------------------------------------------------------ | -------------- | ------------------------------------------------------------------------------------------- |
| Three basic fields; nine main route sliders moved to Advanced            | Build          | Reduces routine mechanism choices while preserving exact source capabilities                |
| Conditional file/warm controls and narrow ineffective-checkbox removal   | Build          | Verified source paths consume different settings; `autoPorts` is ignored by file candidates |
| Preserve fit and preview removed refinements                             | Build          | Existing writer drops authored fit; Keep/Undo must preserve reviewable intent               |
| Current-result card, fewer displayed alternatives, tradeoff labels       | Build          | Smaller presentation can preserve the full method pool and current result                   |
| All ten rebuild engines, Separate, six recipes, exact source values      | Defer deletion | Tested reductions failed; retained semantic and niche witnesses remain useful               |
| Six-engine/eleven-configuration comparison pack                          | Explore        | Useful development compression; fails heldout as a replacement portfolio                    |
| New route presets and automatic numeric policies                         | Explore        | Conditional gains include hard regressions; inspectable alternatives need adverse witnesses |
| Fixed universal Improve dispatcher                                       | Explore        | Cold and warm denominators differ; Separate's local gains do not prove global-task success  |
| Direction lock versus fit search                                         | Explore        | Requires a clear source contract; first disclose current precedence                         |
| Complete capability registry or generic evaluation platform              | Defer          | Direct conditions and a small witness set solve the immediate problem                       |
| New recipe wizard, scratch-tool redesign, brush tuning                   | Defer          | Preserve access; these are not needed for the main-panel reduction                          |
| Diagnostic flags as routine controls, silent side clearing, library swap | Avoid          | Adds burden or removes authored meaning without supporting evidence                         |

Preserve separate node/rank/group gaps and endpoint/line spacing in Advanced. A single generic
spacing scalar did not replace their tested value. Keep numerical iteration budgets internal
where the source path already fixes them; this does not introduce a newly learned preset.

The [implementation plan](implementation-plan.md) refines Pro's plan in three ways: direct path
conditions suffice; presentation changes precede policy changes; current Improve behavior stays
until a replacement is validated. The [asset index](assets/pro-results/2026-11-01/README.md) retains
every original report and companion.
