# Independent review replay code

These files preserve the Python bodies that the independent reviewer actually
executed in transient tool cells. They were recovered from the visible tool-call
history during final packaging. Shell heredoc delimiters were removed; the
Python bodies in the five files named `executed_*.py` were retained, including
their original paths and reporting statements.

**The checks were not rerun while these files were packaged.** Packaging performed
Python syntax parsing only. `replay.py` is a new, separately identified portability
launcher; it was not the program used for the original review and has not been
used to rerun the checks.

The scripts require no notebook variables, hidden cache, network connection,
product execution, or fitted state outside the delivered files. They consume the
raw task/results files, frozen policy, existing analysis tables, and saved geometry
archives. The integrity checks serialize existing geometry signatures and compare
documents; they do not call a layout, compiler, renderer, or router.

## Requirements and commands

The original environment used Python **3.12.14**, NumPy **2.3.5**, and Node.js
**v24.22.1**. NumPy is required for the pre-outcome and routing checks. Node must
be on `PATH` for the two integrity checks that invoke the frozen
`evaluation/verify-control-archives.mjs` serializer.

Run these commands from the delivered bundle root, the directory containing
`evaluation/`, `data/`, and `corpus/`:

```bash
python3 -B evaluation/reviews/replay.py edit-integrity
python3 -B evaluation/reviews/replay.py edit-arithmetic
python3 -B evaluation/reviews/replay.py preoutcome-routing
```

The routing reconciliation and decision follow-up originally wrote the routing
review JSON. To preserve the delivered review, run them in a **copy of the
bundle** and explicitly permit those reporting writes:

```bash
python3 -B evaluation/reviews/replay.py routing --write-review-json
python3 -B evaluation/reviews/replay.py routing-decision --write-review-json
```

Run `routing` before `routing-decision`. The latter uses the review generated by
the former. Neither command changes raw results, frozen policy, frozen code,
scoring rules, or proposal choices.

The launcher locates the bundle from its own file path and substitutes exactly
one original `root=pathlib.Path(...)` literal before executing the recovered
body. It makes no arithmetic, threshold, eligibility, selection, or metric
substitution. The original root was
`/workspace/scratch/8279601ec156/deliverables`; the edit and pre-outcome cells
originally ran from its parent and used `Path('deliverables')`.

Do not use Python's `-O` flag: the analytical and decision checks use assertions.
The output prints discrepancy lists as well as counts; an exit code alone is
not the complete result. In particular, the recovered arithmetic scripts
accumulate some discrepancies rather than raising for every mismatch.

## Scope of the independent arithmetic

The heldout E arithmetic recomputes validity, guard choice, cost addition,
stable-score formulas, exact contributing counts, and deterministic whole-base
bootstrap summaries. It checks references against task declarations. It counts
color-equality flags from the frozen derived records. The separate integrity
snippet verifies their canonical output/reference geometry signatures.

Movement, side-churn, and elementwise color geometry comparisons were originally
derived by the frozen `derive-edit-metrics.mjs` helper. This independent review
did **not** implement a second movement/churn engine or rerun that derivation.
The relevant primary replay command is documented with `analyze-edits.py`; the
independent scripts verify the derived arithmetic and its input integrity.

The routing reconciliation reconstructs scores and acceptance from raw canonical
JSONL metrics and the frozen rule definitions. It checks all 330 main summary
rows' count fields, every reconstructed per-job score/acceptance record, direct
validity summaries, and the named representative bootstrap fields. It does not
claim to independently regenerate every CSV presentation or every uncertainty
cell in every family table.

The pre-outcome check installs a Python file-open hook that rejects every
`.jsonl` read. It evaluates synthetic examples and task/policy definitions only.
It is reproducible after the experiment, but replaying it now does not change its
recorded historical pre-outcome timing.

## Descriptive source review, not separately executed tests

The following conclusions in the review JSONs also depend on inspection of the
delivered source or existing artifacts; no newly written script is being passed
off as an originally executed test for them:

- The analyzer's default mode avoids outcome loading, its scoring calls do not
  fit new policies, and integrity verification precedes result publication.
- The heldout E catalog's broad `*-heldout.jsonl` scan was a read-scope deviation.
  The executed arithmetic verifies that actual E reference IDs are C/E rather
  than H; the causal explanation of the scan comes from source inspection and
  the preserved deviation manifest.
- The projected-direction field is not a universal direction-compliance gate.
  This is a source/contract limitation, not a new geometry experiment.
- The file-auto-ports probe's 12 passing checks were inspected from its existing
  result. The independent reviewer did not rerun that probe. Its own executed
  implementation is `evaluation/probe-file-auto-ports.mjs`.
- The original review interpretations—such as retaining source defaults and
  treating route unions as oracle upper bounds—apply the frozen contract to
  the checked counts. They are not an additional optimization or user study.

## Provenance

`provenance.json` records the recovery source, original tool-cell identifiers,
file hashes, original observed result counts, the new launcher's status, and
the syntax-only packaging check. The `executed_*.py` files were copied from
actual executed tool inputs, rather than constructed after the fact to resemble
an audit. No analysis or product geometry was rerun during recovery.
