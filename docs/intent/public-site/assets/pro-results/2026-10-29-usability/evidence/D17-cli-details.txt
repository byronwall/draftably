It refuses when the file changed since the run.
Drawing conflicts

check also measures the drawing and reports conflicts as warnings. Layout and routing avoid them on their own, so a conflict usually comes from a refinement. Each warning ends with its rule:

Rule	Meaning
edge-through-node	A line runs through a box that is not one of its ends.
edge-through-title	A line crosses a group's title.
node-overlap	Two boxes overlap (across scopes; siblings are an overlap error).
label-collision	An edge label covers a box or another label.
outside-group	A box sits outside its group's frame.
note-overlap	A note with near= found no clear spot beside its object.

When a refinement on one of the objects caused it, the warning names its line and a fix:

Copy
warning line 13: Edge call (web -> api) runs through cache. Remove the pin on line 13, or change it to x=0 y=-64. [edge-through-node]

check --hints adds a table with one row for each object a refinement names: its id, the refinement and line, where layout alone puts it (raw), where it is drawn (final), and the distance between them. A last line lists objects that moved only because a refinement pushed them. inspect --json --hints adds raw: {x, y} to every node a refinement moved. Raw positions come from the same file compiled without its refinement lines.

check --metrics measures the drawing as vary does and prints one line: size and aspect, crossings, bends, total line length and warnings. It also warns on how the drawing reads:

Rule	Meaning
crossing	Two edges that share no end cross. (The metrics line counts every crossing the router sees.)
detour	A route is over 2.5 times, and 300px more than, the distance between its ends.
stranded	A node is over 480px from every node it connects to.
aspect	Wider or taller than 3:1, or with --fit <shape>, more than 1.5 times off that shape's aspect.

inspect --json --metrics adds the same numbers as a metrics object, so a script can compare two versions of a file without drawing an image.

skill install copies the agent skill in skills/draftably, which teaches coding agents to write and check .draft files. --global installs it under ~/.claude/skills, --dir names another skills folder, and --force replaces an existing copy. npx skills add byronwall/draftably installs the same skill from the repository.

open serves a folder: the current folder, the folder you name, or the current folder around the file you name. Without a file, the viewer starts on a page that lists every .draft file in the folder (skipping dot folders and node_modules), creates a new one, or opens an example. Each file opens at ?file=path/in/folder.draft, so links and reloads keep it.

open watches the open file. Edits made in another program appear in the viewer at once. If the source becomes invalid, the viewer keeps the last valid drawing and shows the error line. During development, DIAGRAM_ROOT=folder pnpm dev serves the same folder from Vite; DIAGRAM_FILE=path/to/file.draft serves the current folder and prints the file's address.
