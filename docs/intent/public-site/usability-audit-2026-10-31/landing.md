# Landing page audit: fix ledger

Audit date: 2026-10-31. Build: `main` at `dd2abab`, the same build that https://draftably.dev serves. The Oct 29 repairs (PRs #323-#330) are not repeated here. `pnpm prove:site` passes 60 of 60 checks, so none of these rows has a site proof today.

## Result

The landing page loads fast, its links work, and the demo teaches the product. Three things need repair first:

1. Two claims on the page are false. A drag does not write one line, and a theme does move boxes.
2. A phone visitor gets sideways scroll, and cannot take an edited demo to the Editor.
3. The demo's Undo deletes typed text. Other demo states show a blank frame or give an empty download.

Inferred audience: a developer who keeps diagrams near code, and who may use a coding agent. Inferred goal: try the demo, then open the Editor or install the CLI.

## Keep these

- **Load:** FCP 144 ms, 401 KB, and 8 requests on the live site. CLS is 0.0001.
- **Demo speed:** the demo draws in 28-63 ms. A drag re-routes lines as the box moves. Touch drag works.
- **Stability:** the feature section does not shift when a variant changes. Page height stays at 2748px.
- **Links:** every link returns 200, except npm, which returned 403 to a script. Back from a card returns to the same scroll position.
- **Round trip:** an SVG and a PNG from the demo both reopen with their source through "choose a file".
- **CLI claims:** in an empty folder, `check`, `compare`, `vary`, `inspect --svg`, `skill install` and Node 22.21 all match the page, on npm version 0.8.0.
- **OpenGraph:** a 1200×630 card, 167 KB, with absolute URLs, a clear headline and a real drawing.
- **Reduced motion:** CSS motion stops, and the "Drag me" hint does not animate.
- **Console:** no errors on the landing page at 390, 768 or 1440.

## Method and limits

- **Browser:** Playwright Chromium, with real mouse, keyboard and touch input.
- **Widths:** 390, 768 and 1440 for all checks. Overflow at 17 widths from 320 to 2560. Also 1440×700.
- **Themes:** the site has no theme control. Dark means the OS preference.
- **Not tested:** real phones, Safari, Firefox, screen-reader speech, and users.
- **Live site:** read-only checks only. State tests ran against a local build of the same commit.
- **Comprehension:** the first-screen scores are expert judgment.
