# Docs usability audit, October 31

This ledger records what a new reader finds in the draftably docs after PRs #314-#317 and #323-#330. It does not repeat the [October 29 audit](../usability-audit-2026-10-29/ledger.md). The rows are ready for fix workers. Nothing here changes product code or docs content.

## Result

The docs site works well on a desktop. Pages load fast, every live example passes, and the reference tables match the parser. The defects sit in three places: touch and narrow screens, shell commands that fail when a reader follows them, and task words that search cannot find.

| Measure             | Result                                                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pages               | 21 topics at 1440, 768 and 390px, in two color schemes: 126 views, no page-level sideways scroll, no console error                                                |
| Live examples       | 19 of 19 render, show an error, reset, expand, copy and open in the Playground with the same source                                                               |
| Code samples        | 30 `.draft` samples run with `check`. 4 fail as whole files: 2 are fragments that the text explains, and F4 and G3 list the other 2. One has false warnings (I4). |
| CLI commands        | 81 runs of the commands and options in the docs, with draftably 0.8.0 from npm. See rows D2, H1 and I1 for the failures.                                          |
| Parser against docs | Every engine and router setting, range and default matches. Rows F2 and I5 list what the docs omit.                                                               |
| Search              | 145 queries typed: 25 have no result. Exact DSL words work.                                                                                                       |
| Load                | First load 368 ms, 401 KB. With 4× CPU and slow 4G: 2.1 s. Layout shift 0.02 or less.                                                                             |
| Site proof          | `pnpm prove:site` passes 60 of 60 on `dd2abab`                                                                                                                    |

Severity: **P1** stops a task or gives a wrong result. **P2** adds friction, and the reader can recover. **P3** is polish.

Rules for the workers:

- **No batch edits `site/SiteNav.tsx` or `site/Shell.tsx`.** Batch A changes the header targets with CSS under `.docs-top` only. If a landing batch changes `.site-nav` rules, run it before or after batch A, not with it.
- **`site/site.css` is shared.** Batch A owns the docs rules. Batch B puts new rules in `docs-nav.css`. No other docs batch edits it.
- **`docs/DSL.md` holds one docs page per `##` section.** Batches F, G and H each own their sections, so their hunks do not touch. Do not reflow text outside your sections.
- **A PR that changes `docs/DSL.md` needs a changeset,** and a commit with a `Skill-unchanged: <reason>` line unless it also edits the skill. See [AGENTS.md](../../../../AGENTS.md).
- **Do not edit `scripts/prove-site.mjs` in batches A-I.** Put your proof in the PR. Batch J adds the journeys.
- **Run the search query list again after batches F, G and H.** New headings change the results. The import docs in the `codex/diagram-import-*` PRs change them too.

## Coverage and limits

- **Audience:** a new visitor who knows diagrams and has not used a text diagram tool.
- **Browsers:** Chromium through Playwright, on the local build of `dd2abab` and on https://draftably.dev for speed and contrast. No Safari, Firefox, real phone, screen reader or user study.
- **Touch:** emulated with Playwright's mobile mode. Pinch was read from the code, not performed.
- **PNG and PDF commands:** run with a Playwright headless shell through `CHROME_PATH`, since system Chrome failed in this sandbox. That failure is a limit of this run, not a product finding.
- **Agent skill:** `skill install`, `--global`, `--dir`, `--force`, `skill print` and each command in the skill's loop ran. `npx skills add` did not run, because it runs a third-party package. No coding agent ran the loop from end to end.
- **Landing demo rows in the saving table:** not tested here. The landing audit covers that page.
- **`reference/`:** the docs do not render it, so it has no rows.
- **Out of scope:** an Editor link in Docs at phone width, and import docs in the `codex/diagram-import-*` PRs.
